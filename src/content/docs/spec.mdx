The specification is the canonical description of lemonfiber: what it must do,
how the system is assembled, and the rules a change is held to. Code cites it.
Pull requests cite it. Nothing lands anywhere in the project without naming an
identifier that already exists in it.

It is **written and checked** in the
[`spec` repository](https://github.com/lemonfiber/spec), and **read here**. Every
page below is that repository's own file at the revision this site pins, and each
one says at its foot which revision that was.

<Aside title="How to cite it">
  Every requirement has a permanent identifier — `B1-R2`, `ARCH-R64`, `GOV-R12`.
  A change cites one in a `Spec:` trailer, and CI refuses the change if the
  identifier does not exist. The identifier never changes meaning and is never
  reused. [How the specification works](/spec/00-overview/how-the-spec-works/)
  is the five-minute version.
</Aside>

## If you were looking for something else

The specification says what must be true. It is not a guide to using the tool.

- To install and run it, start at [Start here](/start/).
- To fix something, start at [When something's wrong](/fixing/).
- To change the project, start at [Contributing](/contributing/), which explains
  how to cite the specification in the change you open.

A plugin adds a service to your stack that lemonfiber does not ship. It is
**data**: one `plugin.toml` describing a service, what it can be relied on to do,
how the stack reaches it, and what must be true before it counts as installed.
It contributes no code to lemonfiber's own process.

lemonfiber writes the container. A manifest names an image pinned to its digest,
a port and whether that port is for this machine or your network, and whether
the service needs your media library mounted. The Compose entry, the proxy
address and the dashboard link are generated from that, and there is no field
in which a plugin could ask for more — no environment, no devices, no kernel
capabilities, no network mode, no fragment of Compose. A service that needs any
of that cannot be a plugin; fork the stack with `--stack-dir` instead. The
reasoning is
[ADR-0021](/spec/00-overview/decisions/0021-a-plugin-is-data-and-lemonfiber-writes-its-container/).

A plugin **adds and never overrides**. A check it contributes to the doctor runs
beside the bundled ones under the plugin's own name, and cannot replace,
reorder or silence one of them. It gets no dashboard panel and no command of its
own, and a remedy it offers is shown to you, never run.

Nothing is installed half-way. A manifest with anything wrong in it is refused
whole, with every fault listed at once; an install whose own proofs or whose
effect on the stack's checks do not hold is put back.

## What is built, and what is not

Everything on this section describes the lemonfiber revision this site pins,
which is ahead of every release: the plugin commands are staged for the next
release and are in no released version yet. At that revision:

- **Built:** installing, listing, updating and removing a plugin from a
  directory on this machine; the proofs and the stack's own checks that gate an
  install, and the reversal when either fails; contributed doctor checks and
  remedies; capability wiring and choosing what fills one; the author's reads
  and `plugin provenance`.
- **Not built:** installing from a git address, and the reviewed catalogue that
  would mark an install _reviewed_ — every install today is recorded as
  unreviewed. Recipes can be declared and checked but are refused, because this
  build offers a plugin nothing that would run one. Of what a manifest may ask
  for in `[requires]`, this build offers only what its
  [extension points](/plugins/extension-points/) need — the names printed
  there under _a plugin declares_ — and refuses any other.

[What is built](/project/whats-built/) is the per-requirement record and
[the roadmap](/project/roadmap/) says which version carries the rest.
